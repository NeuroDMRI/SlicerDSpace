## 实现

新增 CLI 可选模式 `--scheduler resources`，在同一台机器的活跃被试间共享计算阶段预约。
原有逐被试滚动并发仍是默认。各被试保留单独进程、依赖、输出、缓存与 QC，
计算阶段通过跨进程文件锁准入，释放资源后继续调度可满足预算的等待阶段。

CPU、RAM 采用声明预约，GPU 采用全局 GPU 型阶段槽位；这些值不构成操作系统硬限制，
也不分配具体显卡或限制单卡显存。对已加载的进程内 PyTorch 推理，释放槽位前同步并
归还未使用的 CUDA 缓存块。被试内部模型并发在该模式下设为一，避免嵌套放大。
没有引入常驻模型、跨被试推理合批或新的推理框架。

异常处理释放当前预约，进程死亡后通过 PID 和创建时间回收失效预约，
所属后代工作进程复用父阶段预约。状态与事件保存在批次记录链接的调度目录中。

## 调度验证

覆盖真实子进程的 CPU/GPU 型阶段重叠、预算核对、嵌套调用、异常退出、失效预约回收、
CUDA 缓存归还、命令参数传递以及合成产物哈希一致性。

三次交替顺序的合成配对使用相同的两个 CPU 预约单位、2 GiB RAM 预算和一个 GPU 型
阶段槽位；每名被试包含 0.2 秒推理等待和 0.4 秒拟合等待。三名被试的墙钟中位数如下：

| 预约粒度 | 墙钟中位数 |
| --- | ---: |
| 整被试预约 | 2.181 s |
| 按计算阶段预约 | 1.432 s |

六次运行的各被试合成输出哈希一致。该实验验证阶段交错和调度开销；负载为等待型合成任务，
基线为整被试资源预约，不是原版本 MRI 全流程。因此这些数值不进入论文的算法加速图。
原始时间、环境与源码哈希见测量数据；完整事件保存在
`ignore/validation/cohort_resources_20261102_verified/`。

## 自动规划更新

普通调用仅需 `--scheduler resources`，可用 `--jobs 3` 设置被试上限；省略时自动选择，
最多八名。新增 `shared/cohort_planning.py` 读取 NIfTI/NRRD 头信息，并结合方法工作空间、
CPU 亲和性、常见容器配额及可用 RAM 生成逐被试阶段预约。
NRRD 的梯度轴依据 `kinds` 归一化。无法读取头信息时记录回退尺寸，不加载整套 DWI。
WMA 等缺少可推导输入规模的阶段保留保守工作空间估计，所有估计均需由实际峰值复核。

手动预算和阶段预约仍优先；单阶段估计超出预算时在启动前报错，不通过缩小分析规模规避。
准入时应用该阶段的线程默认值，退出后恢复，已加载数值线程池通过可用的 threadpoolctl
限制。GPU 型阶段仍默认一个槽位。自动计划与估计依据写入批次记录和调度配置。

新增测试覆盖自动与指定并发、方法/尺寸差异、手动覆盖、异常头信息、NRRD 梯度轴、
容器配额、预算不足及阶段线程默认值恢复。上述合成配对表保留原始实验记录，不改写为
自动规划后的新实测性能。
